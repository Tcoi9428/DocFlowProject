# Architecture

## Стек

- Python.
- Django 5.
- SQLite для прототипа.
- Планируемая БД для эксплуатации: Microsoft SQL Server 2019.
- HTML-шаблоны Django.
- CSS в `static/css/app.css`.

## Django-Приложения

Основное приложение:

```text
documents/
```

Ключевые модули:

```text
models.py            модели данных
forms.py             формы создания, редактирования и согласования
views.py             экраны и обработчики запросов
services.py          бизнес-логика согласования, уведомлений и аудита
admin.py             настройка Django Admin
context_processors.py данные уведомлений и счетчиков для всех шаблонов
user_display.py      единый формат отображения пользователей
templatetags/        template-фильтры
tests.py             автотесты
```

## Основные Модели

- `Department` - подразделения.
- `UserProfile` - профиль пользователя: подразделение, отчество, должность, телефон.
- `CorrespondenceDepartment` - справочник кодов подразделений для номеров корреспонденции.
- `CorrespondenceSequence` - отдельные атомарные счетчики входящих, исходящих писем и служебных записок.
- `CorrespondenceRecord` - запись реестра корреспонденции, черновик и подписанный файл.
- Исторический импорт сохраняет исходный номер, строку Excel, имя исполнителя из старого
  реестра, номер и дату документа отправителя. Технические последовательности архивных
  записей не участвуют в резервировании новых номеров.
- `DocumentType` - тип документа.
- `ContractKind` - вид договора.
- `DocumentPurpose` - назначение документа.
- `CustomFieldDefinition` - пользовательские поля по типам документов.
- `ApprovalRoute` - шаблон маршрута согласования.
- `ApprovalStep` - этап шаблонного маршрута.
- `Document` - документ.
- `DocumentApprover` - пользовательские согласующие конкретного документа.
- `Attachment` - вложение.
- `ApprovalTask` - задача согласования.
- `RevisionRequest` - отдельное замечание согласующего и информация о его устранении в новой версии.
- `DocumentComment` - комментарий к документу.
- `Notification` - внутреннее уведомление.
- `EmailDelivery` - очередь и журнал отправки email-уведомлений.
- `AuditLog` - журнал действий.

## Нумерация

Системный номер генерируется в `Document.generate_system_number()`.

Формат:

```text
КОДТИПА-ГОД-00001
```

Примеры:

```text
DOG-2026-00001
SZ-2026-00001
PRK-2026-00001
VND-2026-00001
PAY-2026-00001
```

Для корреспонденции используется отдельный формат:

```text
КОДВИДА-КОДПОДРАЗДЕЛЕНИЯ-ПОРЯДКОВЫЙНОМЕР
```

Пример исходящего письма подразделения «Инжиниринг»: `01-02-657`, пример служебной
записки: `03-02-669`. Порядковая часть резервируется при открытии формы в транзакции с
блокировкой счетчика, поэтому параллельные пользователи получают разные номера. Стартовое
значение каждого счетчика настраивается в Django Admin. Администратор может уменьшить его
после удаления ошибочных записей; уже занятые номера система при резервировании пропускает.

Утвержденные Word-бланки исходящего письма и служебной записки хранятся в
`documents/document_templates/`. При скачивании система подставляет данные формы, сохраняет
сгенерированный файл в `media/` как черновик и отдает ту же версию пользователю.

## Согласование

Логика согласования находится в `documents/services.py`.

Основные функции:

- `start_approval`
- `approve_task`
- `reject_task`
- `return_for_revision`
- `delegate_task`
- `notify_approval_required`
- `notify_status_change`
- `log_action`

Если у документа есть пользовательские согласующие `DocumentApprover`, они используются приоритетно.

Если пользовательские согласующие не заданы, используется шаблонный маршрут `ApprovalRoute`.

Выбранный пользователем тип маршрута сохраняется в `Document.approval_route_type`. В параллельном маршруте все участники получают задачи одновременно. Первое замечание сразу переводит документ в статус «На доработке», но не закрывает задачи остальных согласующих. Ответственный обрабатывает каждое замечание отдельной формой и обязательно прикладывает новую версию файла. Каждая такая операция увеличивает версию документа и создает повторную задачу только для автора замечания; уже согласовавшие участники повторно документ не согласовывают.

Миграция `0016_enable_existing_parallel_revisions` переводит существующие неудаленные
параллельные документы из `on_approval` в `returned`, если у них есть открытые замечания
любой версии. Если ответственный не указан, назначается инициатор. Задачи, версии, файлы
и история решений сохраняются. Обратная миграция не отменяет этот перевод, чтобы не
затронуть последующую работу пользователей. Завершение параллельного маршрута учитывает
все открытые замечания и ожидающие задачи независимо от версии.

## Уведомления

Уведомления хранятся в модели `Notification`.

Глобальные счетчики и последние уведомления передаются в шаблоны через:

```text
documents/context_processors.py
```

Открытие уведомления помечает его прочитанным и переводит пользователя по ссылке уведомления.

Для пользователя с заполненным email при создании уведомления формируется `EmailDelivery`.
Письмо отправляется после фиксации транзакции и содержит абсолютную ссылку на DocFlow.
Неудачная отправка сохраняется со статусом и повторяется командой:

```text
python manage.py send_notification_emails
```

Команда `send_approval_reminders` создает одно напоминание для активной задачи, если до срока
согласования остался один день или меньше. Повторное напоминание создается только после изменения
дедлайна задачи.

При полном согласовании документа уведомляются инициатор и ответственный, если это разные
пользователи. При возврате на доработку уведомляется ответственный.

Режим технических работ реализован middleware `documents.middleware.MaintenanceModeMiddleware` и
включается переменной `DOCFLOW_MAINTENANCE_MODE`. В этом режиме Django отвечает кодом `503`.
Для неизвестных адресов при `DEBUG=False` используется пользовательская страница `404`.

## Вложения

Файлы сохраняются на диске в `media/`.

В базе хранятся:

- путь к файлу;
- исходное имя;
- версия документа на момент загрузки;
- дата и автор загрузки;
- размер;
- SHA-256 hash.

Для ответа на замечание `RevisionRequest.resolution_attachment` хранит ссылку на конкретный файл исправленной версии.

Максимальный размер файла задается в настройках через `MAX_UPLOAD_SIZE`.

## Переход На SQL Server

Для перехода на Microsoft SQL Server 2019 потребуется:

- установить ODBC Driver for SQL Server;
- установить `mssql-django` и `pyodbc`;
- изменить `DATABASES` в `docflow_project/settings.py`;
- выполнить миграции;
- настроить хранение `media/` на серверном диске;
- настроить бэкапы БД и файлов.
