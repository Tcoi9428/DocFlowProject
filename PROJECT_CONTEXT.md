# Project Context

## Назначение

DocFlowProject - прототип внутреннего веб-сервиса документооборота для компании, занимающейся проектированием, ремонтом и техническим обслуживанием шахтной техники.

Основная цель: заменить ручное согласование документов простым веб-инструментом без перегрузки пользователей лишним функционалом.

## Пользователи

Ожидаемая нагрузка:

- 20-25 активных пользователей.
- Менее 100 документов в месяц.
- Вложения до 20 МБ на файл.
- На прототипе доступ в локальной сети, в будущем возможна публикация через интернет.

## Документы

Базовые типы документов:

- Договоры.
- Служебные записки.
- Приказы.
- Внутренние документы: инструкции, методики, положения.
- Счета/УПД и заявки на оплату работ.

Для всех документов есть:

- системный номер;
- внутренний номер компании;
- тип документа;
- тема;
- инициатор;
- ответственный;
- подразделение;
- даты;
- вложения;
- маршрут согласования;
- комментарии;
- журнал действий.

Для договоров дополнительно используются справочники:

- виды договоров;
- назначение документа.

## Бизнес-Логика

Документ можно:

- создать;
- редактировать в статусе черновика или возврата;
- отправить на согласование;
- согласовать;
- вернуть на доработку;
- отклонить;
- делегировать согласование;
- архивировать.

Маршрут согласования может быть:

- шаблонным, созданным администратором;
- пользовательским, заданным при создании документа;
- последовательным;
- параллельным.

## Безопасность

Текущий прототип использует стандартную авторизацию Django: логин и пароль.

Требования:

- все документы видит только администратор или пользователь с правом `view_all_documents`;
- обычные пользователи видят свои документы, документы где они ответственные, и документы где они согласующие;
- физическое удаление не используется, документы помечаются как удаленные;
- действия пользователей логируются в журнале.

## Технический Контекст

Текущая разработка ведется на SQLite для быстрого прототипирования.

Целевая среда:

- Windows Server 2019 Standard;
- SQL Server 2019;
- Python;
- отдельный веб-сервис;
- хранение файлов на диске сервера;
- хранение ссылок и hash файлов в базе данных.
